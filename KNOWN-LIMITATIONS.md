# Known limitations and open decisions

The original plan is implemented except the items below, which are intentionally incomplete or blocked. The largest open item is `Vec<T>` (core-language phase 7); the raw moves it needs, `__builtin_read` and `__builtin_write`, are implemented.

## Platform support
- **macOS raw threads:** `bsdthread_register` returns `EINVAL` in a process that did not come up through
  libSystem, so `bsdthread_create` could not be tried. The scheduler runs cooperatively on one thread
  there; kqueue I/O works. Options: find the registration prerequisite, use Mach `thread_create_running`
  (MIG message), or keep the single-thread mode.
- **Windows:** `std/sys/windows.xl` imports ntdll `Nt*`, ws2_32 (sockets), bcrypt (RNG) and `GetStdHandle`
  with `@library("...") declare fn`; the clock is read from `KUSER_SHARED_DATA`. A program cross-compiles and
  links (`--target x86_64-pc-windows-msvc`, import libraries generated by `llvm-dlltool`). **Tests:**
  `test/e2e/run.sh` builds every Windows-capable e2e program as a Windows executable and runs it with
  `cxrun <exe>` (CrossOver/Wine; skipped when `cxrun` is not on `PATH`): language, stdlib, file/JSON, all
  hash/AEAD/ECDSA/X25519 programs, and the TLS 1.3 server + client and HTTPS server + client pairs (RSA and
  ECDSA certificates, the 200000-byte transfer, host-name and root rejection) pass with the same results as
  macOS and Linux. **Not** run on real Windows (Wine's winsock/crypt32 are not Windows'), and the
  `sched`/`threads`/`panics` e2e programs are not run there. The entry stub (`mainCRTStartup`) exits through
  `NtTerminateProcess` and provides `__chkstk`/`_fltused` itself. Not done: threads (`NtCreateThreadEx` +
  `WaitOnAddress`), readiness polling (IOCP/AFD), pipes; UTF-8 paths are widened as Latin-1; the fd is the
  handle's low 32 bits (socket fds carry bit 30); `-D ssn...` no longer exists. Entry stubs exist for linux and macos on x86_64 and aarch64 and for windows on x86_64 only; the Windows stub is x86_64 assembly with no aarch64 variant. Every stub calls `_xl_initAll` (the `@init` functions) before `main`.
- **Linux/macOS sockets ignore SIGPIPE** (`std/sys`: process-wide on Linux, `SO_NOSIGPIPE` on macOS), so a
  write to a vanished peer is an error return, never a crash.

## ABI and interop
- **`export(c)` and aggregates by value:** structs are passed/returned through pointers (the xl convention),
  not through the target C ABI (SysV/AAPCS register passing). Only pointers, scalars and `@repr(c)`
  structs behind pointers are safe across the boundary.
- **Itanium typeinfo:** the vtable of an `@repr(c)` class has a `null` typeinfo slot; no `_ZTI...` symbol.

## Language/stdlib
- Control flow: `while`, `do { } while c`, `for init; cond; step { }`, `for i in lo..hi { }` (`hi` exclusive,
  integer bounds, evaluated once), `break`, `continue`, labels (`outer: while ...`, `break outer`, `continue outer`;
  `continue` in a `for` runs the step), `switch v { case a, b { } default { } }` (integers, bools, enums; no
  fallthrough; a `break` inside a `switch` leaves the enclosing loop, the `switch` is not a break target),
  `defer stmt` (runs when the enclosing block is left, including by `return`/`break`/`continue`, last-in
  first-out; the deferred statement cannot itself `return`, jump, declare a variable or `defer`; `return v`
  computes `v` before the deferred statements run), `cond ? a : b`, compound assignment (`+= -= *= /= %= &= |= ^=
  <<= >>=`) and statement-level `x++` / `x--`. `a op= b` is `a = a op b`; a target containing a call is
  evaluated once through a hidden pointer. `++`/`--` are lexed as tokens, so `a--b` no longer parses as `a - -b`:
  write `a - -b`. Break/continue across a `switch` or `for` header are not otherwise restricted.
- Generics (core-language phase 6) are instantiated per use (monomorphized). Not done: generic interfaces, generic `impl`
  blocks, constraints on type parameters, explicit type arguments on class methods, and generic function values without
  a call (`E0724`). Generic instances are not `linkonce_odr` (the whole program is one module). Expression-level
  `f<T>(x)` is recognized when the `>` is followed by `(` or `{`, so `i < j > (k)` is a generic call. `__builtin_needsDrop`
  and `__builtin_drop` take their type with `<...>`, not as an argument, because a type is not an expression. An error
  inside an instance is followed by one "in instantiation of" note per level, at most 8.
- **Boot and registrations (core-language phase 10).** The generated init entry is `_xl_initAll`, not `$xl$initAll`
  as the plan said: in the raw AT&T entry stub a `$` that starts an operand is an immediate prefix, so
  `call $xl$initAll` would not assemble. The Linux and macOS paths are verified only through the Docker e2e runs.
  **Allocator replacement is not tracked per block:** after `__builtin_setRegistered("allocator", v)`, `new`, `delete`,
  `free` and `String` all use `v`, so a block allocated before the replacement and freed afterwards goes to `v.free`. The
  compiler does not check the pairing. `std/sched` keeps using `Heap` and `sysMap` directly and is not redirected. An
  A bodyless `@init fn boot();` is the parser's `E0002`; the sema check for a missing body in `E0729` is therefore only a
  guard.
- No tuples/multiple return values (not defined by the plan).
- **`Vec<T>` (core-language phase 7) is not implemented.** Slots are written with `__builtin_write` and read with
  `__builtin_read`; the container itself is not written yet.
- `String` (core-language phase 7): the HTTP and TLS modules still use `*ui8` buffers. `fsReadAllString` is in `std/fs`.
- `const` (core-language phase 2): a `const` is not a `define` constant, so it cannot be an array length, a `staticAssert`
  operand or a `define` argument. Its initializer cannot read another variable or `const` (a `GlobalRef` is not a compile-time
  value), and an untyped module-level `const` takes only the default type of a literal (an enum member or an array needs
  `: T`). Block-level `const` names are not `define` names: they are read-only globals with a unique symbol.
- Ownership (core-language phase 5): drops are statically dispatched (deleting a derived object through a base pointer runs
  only the base drop). There is no explicit base constructor call: a derived `init` runs the base's argument-less `init`
  automatically. An array whose element needs drop is `E0721` at locals, parameters, fields and globals, because arrays do
  not drop their elements. `delete(a)` needs an interface allocator value. Temporaries used as receivers are materialized with a drop flag; a droppable temporary inside `&&`/`||`
  or a `?:` branch is dropped only if it was created.
- Overloading (core-language phase 3): an overloaded function's HIR name is its qualified name plus its mangled parameter
  types (not the link symbol); this is the unique key codegen uses. Overload resolution lowers each non-literal argument
  once, with no expected type, so an array literal passed to an overloaded or generic call has no element type context
  and must be written with a typed local. Nested overloaded calls cost time linear in their size. Class-to-base pointer
  conversion is not an implicit conversion in this language, so it does not count as a candidate. Virtual methods are not
  overloadable (`E0405`); `init` constructors are.
- `str` (phase 1 of the core-language work): no `==`/`!=` in the compiler (`strEq` in std), no implicit or `as`
  conversion to `*ui8` (only `.ptr`), no way to make a `str` from a pointer except `std/str` (`strFromParts` reinterprets a
  `@repr(c)` two-word struct). A `str` view does not keep its bytes alive: the caller must. Writing through the `*ui8` of a
  literal is undefined behavior (its bytes are in read-only data); `[ui8; N]` is the writable form. `std/http` and the TLS
  modules still pass `*ui8` pointer and length pairs; their `strEq` is named `cstrEq` to avoid the name of `std/str`.
- `W0701`: a function with a return type can reach its end without `return`. The analysis is syntactic: every
  path must end in `return`, an infinite `while true` without `break`, `__builtin_asm(..., options("noreturn"))` or
  a call to the registered `panic`. Other `noreturn` callees are not recognized (a warning, not an error).
- Bit operators `& | ^ ~ << >>` exist with Go-style precedence (`& << >>` bind like `*`, `| ^` like `+`,
  so `a & b == c` is `(a & b) == c`). Shifts: the result has the left operand's type, the count may be any
  integer type, a count >= the bit width gives 0 (`>>` of a negative signed value gives -1), `>>` on signed
  types is arithmetic. In `define`/global constants `~x` is the untyped `-x - 1`; cast the result.
- `HIR` does not fold constant expressions (`N * 2` is constant in global initializers but folded later).
- Module resolution: `std`/`std/x` come from the stdlib root; other paths from the importing file's
  directory, then the root file's directory. `import "x"` without alias binds the last path segment.
  No package or search-path strategies.
- The default stdlib is embedded in the compiler (generated `build/gen/std_blob.cpp`, rebuilt when
  `std/**/*.xl` changes); `--std=<dir>` replaces it. The compiler never searches the file system for it.

## Stdlib: files, JSON, HTTP
- **`std/http`:** the server speaks HTTP (`routerServe`) or HTTPS (`routerServeTls`, TLS 1.3; one connection
  at a time, blocking `accept`, `Connection: close`; a slow client stalls everyone for up to the 20 s receive
  timeout). The router is Gin-style (`:name`, `*name`, groups, middleware chains, 404/405, trailing-slash
  redirect). Limits: path 127 bytes, 7 middleware per route, 8 route parameters (512 bytes total), 1024 bytes
  of response headers; registration beyond them panics or fails. Request bodies need `Content-Length` (chunked
  request bodies are not supported); the request buffer is capped by `maxHeaderBytes`/`maxBodyBytes`. There is
  no panic recovery middleware, no body binding and no template/static-file helpers. Routes are matched by a
  linear scan (static first), not a radix tree.
  The client is `fetch*`/`httpOpen` (http and https, redirects, streaming bodies, every method); it has no
  cookies, keep-alive, compression, proxy, IPv6 or HTTP/2. Source is split in `std/http/*.xl`.
- **`std/tls` is TLS 1.3 only, client and server:** X25519 key exchange, suites `TLS_CHACHA20_POLY1305_SHA256`
  (preferred) and `TLS_AES_128_GCM_SHA256`; no TLS 1.2 or older (a TLS 1.2-only peer fails with `TLS_ERR_VERSION`;
  the server answers it with a `protocol_version` alert), no session resumption/0-RTT/NewSessionTicket, no
  HelloRetryRequest (a client without an X25519 key share, or a server that insists on another group, fails with
  `TLS_ERR_RETRY`), no AES-256-GCM-SHA384, no client certificates (the client sends an empty Certificate when
  asked; the server never asks), no ALPN, SNI is sent but the server ignores it (one certificate per
  `TlsCredentials`, no virtual hosting). **Server keys:** PEM PKCS#8, PKCS#1 RSA or SEC1 EC (RSA up to 4096 bits
  signing rsa_pss_rsae_sha256; ECDSA P-256 / P-384; no Ed25519, no encrypted keys); a chain of at most 60000
  bytes; the leaf's key type must match the key. **Signing is not constant-time** (square-and-multiply and
  double-and-add on the secret; `k` for ECDSA is random, not RFC 6979): do not expose the server to a local
  attacker who can time it. Interop is verified against OpenSSL 3 `s_client` (both suites, RSA and ECDSA) in
  manual runs; the e2e suite uses the in-repo client. The test key pairs under `test/e2e/tls/` are public. Certificate
  validation (`std/truststore`, `std/x509`): chain to an OS root, validity period, `subjectAltName` DNS names
  (CN is ignored, IP SANs unsupported), CA/keyUsage/pathLen; **not** checked: revocation (CRL/OCSP),
  nameConstraints, extended key usage, critical extensions, certificate policies. Signatures: RSA PKCS#1/PSS and
  ECDSA P-256/P-384 (no Ed25519, no P-521). Root stores: Linux PEM bundles (`/etc/ssl/certs/ca-certificates.crt`
  and distro variants), macOS `/etc/ssl/cert.pem` (the keychain itself is not read), Windows: the system `ROOT`
  store through crypt32 (roots Windows would still fetch on demand from Windows Update are absent until used;
  enterprise/policy stores are not read; 4 MiB cap). The crypto is not constant-time (AES S-box, bignum),
  fine for a client verifying public data but not for secrets shared with a local attacker. Handshake messages
  are limited to 64 KiB and 8 certificates. The root bundle is cached unlocked (two threads racing the first
  load leak one mapping).
- **`std/json` is read-only and flat:** lookups of top-level members of an object in a NUL-terminated buffer;
  no nested paths, no `\u` escapes, no validation, no writer.
- **`std/fs` has no directories or metadata** beyond existence and size; the caller supplies all buffers.

## Testing
- **`std/testing` has no discovery:** a test file registers its tests explicitly (`test(&s, "name", fn)`) and
  returns `suiteRun`. Auto-discovery of `fn test*` would need reflection or a compiler-side convention.
- **No chained matchers** (`expect(x).toEqual(y)`): there are no generics, so the matchers are typed
  functions (`expectEq` for `i64`, `expectEqUInt`, `expectEqStr`, `expectNear`, ...).
- **A failed expectation does not stop the test** (no unwinding); a `panic` ends the whole file's run, which
  `xlang test` reports as that file failing.
- **`xlang test` runs files sequentially** (no `--jobs`) and has no per-test name filter; granularity is the
  file. Windows is not supported by the runner (POSIX `fork`).

## Tooling
- Debug info has compile unit, subprograms, line locations and basic types; no struct/class types.
- `--incremental` caches per-module objects only; semantic analysis still runs for every module (no
  interface files). A MIR layer (plan 8.3) was not needed.
